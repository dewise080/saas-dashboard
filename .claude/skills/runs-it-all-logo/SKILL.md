# Runs It All Logo Orchestrator

Use these installed project skills in order:
1. `brand-foundation`
2. `logo-maker`
3. `logo-sad`

Do not skip directly to image generation.

## Stage 1 — Brand Thesis
Read the current product/repo context and establish the product promise, audience, emotional target, category, core metaphor, anti-reference list, and the one idea the logo must communicate.

Runs It All is not merely WhatsApp automation. It is intended to become a cross-channel customer-operations system spanning replies, follow-ups, booking, payments, reminders, reviews, feedback, broadcasts, channels, calls, analytics, and business-gap detection.

The identity should therefore communicate a broader promise: the customer-facing side of the business keeps moving with less manual work.

## Stage 2 — Concept Architecture
Generate 8–12 written logo concepts before rendering. Each must be a different idea, not a color or layout variation.

Explore at minimum:
- many-to-one
- continuity
- orchestration
- command/control
- leverage
- coverage
- custom wordmark
- letterform-derived concept only if it earns its place

For each concept specify the concept name, core meaning, geometric logic, emotional signal, distinctiveness rationale, favicon behavior, and why it belongs specifically to Runs It All.

## Stage 3 — Reject Weak Concepts
Before rendering, remove concepts that are generic SaaS marks, arbitrary R monograms, chat bubbles, robot/AI heads, sparkles, generic infinity marks, gears, generic connected nodes, rainbow-gradient abstractions, or marks whose explanation could fit unrelated startups.

Select only the strongest 5–6 for visual exploration.

## Stage 4 — Black & White First
Render first-round logo concepts primarily in black and white so form, silhouette, and meaning can be judged without color influence.

Show each as:
- mark only
- mark + Runs It All wordmark
- 16px/32px small-size test
- dark-background reverse

Do not lead with polished mockups. The first decision is about the mark itself.

## Stage 5 — Owner Selection
Use a hard selection process: KEEP or REJECT. Do not average rejected concepts into surviving directions. Mutate each surviving direction independently in the next round.

## Stage 6 — SAD Review
For every survivor run `logo-sad`: Simple, Appropriate, Distinct.

Place finalists against relevant competitors such as Respond.io and adjacent CRM/customer-operations/AI-agent brands. If a mark visually collides with a famous or category-leading logo, reject it.

## Stage 7 — Color & Wordmark
Only after the form survives:
- develop color system
- refine wordmark typography
- test horizontal and stacked lockups
- build app icon and favicon
- test website header, dashboard, social avatar, and monochrome use

Prefer restrained premium color behavior. Avoid gradients as a substitute for concept strength.

## Stage 8 — Explain the Logo
Every finalist presentation must include:
1. The mark
2. The one-sentence idea
3. The deeper brand meaning
4. Why each shape exists
5. What emotion it creates
6. Why it is distinctive in the category
7. Small-size behavior
8. Black/white behavior
9. App icon behavior
10. Weakness/risk

Reject vague explanations like “blue means trust” unless tied to a specific, defensible system choice.

## Stage 9 — Production
After final approval, produce a locked identity system with SVG lockup, standalone icon, inverse, black, white, grayscale, favicon, app icon, PNG exports, clear-space/minimum-size rules, and misuse rules.

Production/export tooling such as LogoLoom may be used only after the mark is selected; it is not the source of the brand idea.
